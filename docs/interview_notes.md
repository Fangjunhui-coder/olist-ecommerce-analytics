# 面试讲解提纲

请结合自己真实参与的工作使用。该项目是对公开历史数据的分析，代码编写和文档整理使用 AI 辅助；没有实施运营活动、上线实验或获得业务提升。不要把策略建议说成实际业务成果。

## SQL 模块逐个说明

1. `00_order_profile.sql`：按订单状态计数并查看下单时间范围，帮助识别样本边界；阶段 0 程序内的对应 SQL 会实际执行。
2. `01_stage0_risks.sql`：检查已送达订单是否缺商品、评价或用户 ID，检查未知品类与一单多评价；先弄清连接是否会丢单或放大。
3. `02_stage1_model.sql`：订单连接客户得到真实用户 ID，再连接商品明细；以订单 ID 为粒度汇总 GMV 和商品件数，避免一单多件放大订单数。按英文、葡语未翻译和未知三种情况保留品类。
4. `03_stage1_outputs.sql`：分别计算整体、自然月、品类、州及其月度汇总；先按用户汇总频次再计算复购；窗口函数计算环比和 GMV 累计占比，首次达到或超过 80% 的品类也纳入。
5. `04_supplementary_metrics.sql`：独立计算运费、含运费 GMV、首单后 90 天复购、日度订单；以最后已送达订单为截止时点再做敏感性比较。首单为样本内首单。
6. `05_rfm.sql`：从全量订单取最后下单日次日作为参照日，在用户层计算 R、F、M；使用连续分位点且同值不拆分，F 以 1 单和 2 单及以上划分。
7. `06_operating_groups.sql`：以互斥的优先规则将 18 个 RFM 组合归并为 6 个运营人群，汇总用户数和商品 GMV，确保可以对账。
8. `07_delivery_analysis.sql`：按自然日期定义延迟并筛除无效时间，按评价回复时间选最新一条，按最高金额商品确定订单主品类，再产生差评组、时长组和州／卖家延迟率。原时间戳口径通过参数切换复算。
9. `08_review_audit.sql`：核查多评价、评分差异、回复和创建时间是否并列，并与 pandas 独立结果对账，支撑评价选取规则。

## 常见问题与回答要点

1. **为什么用 `customer_unique_id`？** `customer_id` 是订单对应的客户记录，同一位买家不同订单可能使用不同 `customer_id`；用户数、复购和 RFM 都应该按 `customer_unique_id` 去重。
2. **为什么只分析已送达订单？** 便于聚焦完成交付的交易和配送体验，但不等于全部交易，也不保证没有退款；接近数据截止时未送达订单被排除，可能产生选择偏差。
3. **GMV 是否含运费，和实收有什么区别？** 主 GMV 为商品价格总和，不含运费；运费和两者之和单列。缺少完整退款、费用和结算信息，不能把它说成净收入或利润。
4. **为什么 F 不做五分位？** 93,358 名买家中有 90,557 人只有 1 单；大量同值无法形成稳定且有区分度的五档。使用 1 单和 2 单及以上，再结合 R、M 描述异质性。
5. **累计复购率与 90 天复购率有何区别？** 累计口径是整个观察期内至少两单买家除以全部买家，结果 3.00%；90 天口径只纳入样本首单日期距全量数据截止日至少 90 天的用户，结果为 1,608/84,462=1.90%。两者分母和观察窗口不同，不可直接比较为效果提升。
6. **90 天指标为什么仍需谨慎？** 最后一笔已送达订单早于全量订单数据截止时点，9,075 名名义成熟用户的窗口延伸到最后已送达订单之后。用较早的已送达截止时点对照为 2.01%，但这也不能证明此前数据完整。
7. **多评价订单怎么处理？** 已送达订单中 525 单有多评价、189 单评分不同；创建日期存在并列。评价回复时间没有并列，因此每单取回复时间最新一条；这只是可复现选择规则，最新不一定更真实。
8. **为什么订单维度不能直接连接所有评价和商品？** 一单可能多商品、多支付或多评价，直接连接会出现多对多膨胀。先按订单或其他明确粒度聚合，再计算订单指标。
9. **延迟怎么定义，为什么还有时间戳对照？** 主口径是实际送达日期晚于预计日期；原时间戳口径判定更严格。由于预计时间均在午夜，1,292 单同日稍后送达会被时间戳口径归为延迟，导致结论有差异。
10. **卡方检验的意义和限制？** 比较延迟与准时订单的差评比例差异，主口径差异为 53.15 个百分点；p 值反映在模型假设下观察到该差异的极端程度，不证明延迟是原因。普通检验将订单视作独立，而同一买家可能多次购买。
11. **OR 怎么解释？** 主模型延迟系数 2.822 对应 OR 16.80，表示控制模型变量后，延迟组差评的优势约为准时组的 16.80 倍；优势比不是概率比，也不是干预后会提升多少。
12. **为什么从全样本 OR 16.80 降至送达后评价子样本的 2.38？** 4,653 条评价早于最终送达，部分客户在预计日期后、收到货前就回复了评价；此时最终延迟时长尚未知。筛选后样本组成和时间顺序发生变化，因此估计明显不同；不能仅凭结果断言唯一原因，子样本筛选也可能造成偏差。
13. **相关与因果有什么区别？** 两组同时存在差异不等于延迟导致差评；商品质量、路线、承运商、客户预期和是否愿意评价等因素可能影响二者。回归控制可观测变量，也无法消除未观测混杂和选择偏差。
14. **真实业务如何验证运营策略？** 先定义合格人群和可触达权限，按用户随机分组，固定 30 天观察窗口，以有再次已送达订单的用户占比为主指标，并跟踪触达／优惠成本和退订率。事先设定样本量和停止规则，按随机分组分析，不把该公开数据当成已做实验。
15. **配送优化如何验证？** 先核查预计日期口径，再拆分揽收、运输、承运商与地区；对可操作的服务流程随机试点或采用可信的分批对照，同时追踪延迟、差评和成本。不要仅凭卖家排名追责。
16. **品类和州有哪些去重风险？** 跨品类订单会在多个品类各计一次，品类订单数不能简单相加。州取客户表；地理位置表邮编不唯一，未经聚合不能直接连接订单。
17. **SQL 和 pandas 对账怎么做到独立？** SQL 从 CSV 建表并生成汇总；pandas 重新读取原始 CSV、自行连接与计算，金额转为整数分求和，逐组比较。`validate.py` 在临时目录复算再检查已保存结果，不会先覆盖结果。
18. **可以声称带来多少增长吗？** 不可以。这里没有实际触达、A/B 测试或线上干预；所有建议仅为待验证假设，数字均为历史样本中的描述或模型估计。

更多分母、置信区间和建议见 `report.md` 与分阶段文档；面试前应重跑并核对输出。
